# دليل تنسيق قسم المخزون والمنتجات

## الغرض من الملف

هذا الملف هو المرجع الأساسي لتنسيق قسم المخزون والمنتجات في النظام الرئيسي. يشرح البنية الصحيحة للقسم، ترتيب العناصر، قواعد العرض على الشاشات المختلفة، المشكلات التي قد تظهر، وطريقة تشخيصها وإصلاحها دون التأثير على شريط البحث العام أو الأقسام الأخرى.

يجب الرجوع إلى هذا الملف قبل تعديل `index.html` أو `css/styles.css` في أي جزء يتعلق بالمخزون.

## الملفات المسؤولة

- `index.html`: يحتوي على بنية قسم المخزون، شريط الترتيب، زر أسعار الميكانيكي، أزرار الفلترة، وحاوية المنتجات.
- `css/styles.css`: يحتوي على قواعد تخطيط القسم والبطاقات والأزرار والحاوية القابلة للتمرير.
- `js/app.js`: يحتوي على `renderInventory()`، وهي الدالة التي تنشئ بطاقات المنتجات داخل `itemsList`.
- `oldxmetal/index.html`: مرجع ترتيب عناصر قسم المخزون القديم.
- `oldxmetal/css/styles.css`: مرجع التنسيق القديم لقائمة المنتجات العمودية.

## البنية الصحيحة في index.html

يجب أن تكون بنية القسم بهذا الترتيب المنطقي:

```html
<div class="section-panel inventory-section-panel" id="section-inventory">
  <div class="inventory-toolbar">
    <select id="inventorySortSelect">...</select>
    <button id="toggleAllMechanicPricesBtn">...</button>
  </div>

  <div class="filter-bar inventory-filter-bar" id="inventoryFilterBar">
    <button data-filter="all">الكل</button>
    <button data-filter="available">المتوفرة</button>
    <button data-filter="outofstock">المنتهية</button>
  </div>

  <div class="items-scroll-wrapper">
    <div class="items-container inventory-products-stack" id="itemsList"></div>
    <button id="inventoryScrollTopBtn">...</button>
  </div>
</div>
```

### ترتيب العناصر

1. شريط البحث العام يبقى في `sticky-search-bar` أعلى النظام، ولا يتم نقله إلى قسم المخزون ولا إنشاء نسخة ثانية منه.
2. داخل قسم المخزون يأتي صف الترتيب وأسعار الميكانيكي أولًا.
3. يأتي صف الفلاتر الثلاثة أسفل صف الترتيب مباشرة.
4. تأتي قائمة المنتجات أسفل الفلاتر.
5. تظهر المنتجات داخل `itemsList` بواسطة `renderInventory()`.

## قاعدة الحاوية الأم

يستخدم النظام `section-panel.active` بأسلوب Flex. لذلك يجب أن يحدد قسم المخزون اتجاهه عموديًا بشكل صريح:

```css
.inventory-section-panel {
    display: flex;
    flex-direction: column;
    width: 100%;
    min-width: 0;
}
```

### لماذا هذا مهم؟

إذا كان القسم يستخدم `display: flex` دون `flex-direction: column`، فإن الاتجاه الافتراضي يصبح `row`. عندها يعامل المتصفح شريط الأدوات والفلاتر وقائمة المنتجات كعناصر بجانب بعضها. والنتائج المحتملة هي:

- ظهور المنتجات في نصف الحاوية.
- ظهور شريط الفلاتر بجانب المنتجات بدل ظهوره فوقها.
- ظهور مساحات فارغة كبيرة.
- تقلص حاوية المنتجات أو خروج محتواها.
- اختلاف النتيجة بين الشاشات بسبب قواعد Flex المتجاوبة.

هذا هو السبب الجذري الأهم الذي يجب فحصه أولًا عند ظهور القسم بشكل نصف حاوية.

## صف الترتيب وأسعار الميكانيكي

يجب أن يحتوي الصف العلوي على عنصرين فقط:

- قائمة الترتيب `inventorySortSelect`.
- زر إظهار أو إخفاء أسعار الميكانيكي `toggleAllMechanicPricesBtn`.

القواعد المطلوبة:

```css
.inventory-toolbar {
    display: flex;
    flex-wrap: nowrap;
    align-items: center;
    gap: 10px;
    width: 100%;
    overflow-x: auto;
}
```

### سلوك الصف العلوي

- يظهر العنصران في سطر واحد.
- لا يسمح للصف بالتحول إلى أعمدة فوق بعضها.
- عند ضيق الشاشة يستخدم التمرير الأفقي بدل تغيير الاتجاه إلى عمودي.
- لا يتم وضع شريط البحث العام داخله.
- قائمة الترتيب لها عرض أدنى مناسب، ويجب ألا تنكمش إلى زر صغير غير قابل للقراءة.

## صف الفلاتر

يجب أن يحتوي `inventoryFilterBar` على ثلاثة أزرار في صف أفقي واحد:

- الكل.
- المتوفرة.
- المنتهية.

القواعد المطلوبة:

```css
.inventory-filter-bar {
    display: flex;
    flex-direction: row;
    flex-wrap: nowrap;
    width: 100%;
    overflow-x: auto;
}

.inventory-filter-bar .filter-btn {
    flex: 1 1 0;
    min-width: 0;
}
```

### مشاكل صف الفلاتر

#### ظهور الأزرار كأعمدة

الأسباب المحتملة:

- وجود `flex-direction: column` على `filter-bar` أو حاوية أعلى منه.
- وجود `display: grid` مع أعمدة غير مقصودة.
- وجود `flex-wrap: wrap` مع عرض صغير جدًا.
- وجود قاعدة CSS لاحقة تتغلب على القاعدة الصحيحة.
- وضع الأزرار داخل حاوية بعرض محدود بسبب اتجاه القسم الأم `row`.

الحل:

1. افحص الاتجاه النهائي في DevTools.
2. تأكد أن `inventory-filter-bar` يستخدم `display: flex` و`flex-direction: row`.
3. تأكد أن `flex-wrap: nowrap` موجود.
4. تأكد أن الحاوية بعرض `100%`.
5. استخدم `overflow-x: auto` عند الحاجة بدل تحويل الأزرار إلى أعمدة.
6. راجع ترتيب القواعد في الملف، لأن القاعدة الأخيرة ذات الأولوية قد تغير الاتجاه.

## قائمة المنتجات

الترتيب المطلوب هو بطاقة أفقية كاملة العرض فوق بطاقة أخرى:

```css
.inventory-products-stack {
    display: flex;
    flex-direction: column;
    align-items: stretch;
    width: 100%;
    gap: 14px;
}

.inventory-products-stack .product-card {
    flex: 0 0 auto;
    width: 100%;
    min-width: 0;
    box-sizing: border-box;
}
```

### معنى بطاقة أفقية

المقصود أن البطاقة تكون عريضة وتمتد من بداية الحاوية إلى نهايتها، وليست بطاقة صغيرة في نصف المساحة. لا يعني ذلك تحويل محتويات البطاقة الداخلية إلى صف واحد؛ بل يعني أن البطاقة نفسها تكون بعرض الحاوية، وتبقى محتوياتها مرتبة وفق تصميم البطاقة:

1. رأس البطاقة واسم المنتج والبيانات المختصرة.
2. صف الأسعار الثلاثة.
3. أزرار العمليات.

### خصائص القائمة

- بطاقة واحدة في كل سطر.
- عرض البطاقة `100%` من عرض الحاوية.
- المسافة بين البطاقات `14px`.
- الاتجاه الداخلي للبطاقة `rtl`.
- الحاوية قابلة للتمرير رأسيًا.
- لا يستخدم قسم المخزون شبكة متعددة الأعمدة للبطاقات.
- لا يضاف `margin-bottom` إضافي للبطاقة إذا كانت الحاوية تستخدم `gap`، لأن ذلك يضاعف المسافة.

## الحاوية القابلة للتمرير

```css
.items-scroll-wrapper {
    position: relative;
    height: calc(100vh - 240px);
    max-height: calc(100vh - 240px);
    min-height: 320px;
    direction: ltr;
}

.items-container {
    height: 100%;
    overflow-y: auto;
    padding: 16px 12px;
    direction: ltr;
}
```

### لماذا الاتجاهان مختلفان؟

- `items-container` يستخدم `ltr` لتثبيت سلوك شريط التمرير ومكانه.
- `product-card` يستخدم `rtl` حتى تظهر معلومات المنتج باللغة العربية بالاتجاه الصحيح.
- لا تغير اتجاه البطاقة إلى `ltr` لحل مشكلة ترتيب القائمة؛ الحل الصحيح يكون في حاوية القائمة.

## بطاقة المنتج ومحتوياتها

يتم إنشاء البطاقة في `renderInventory()` داخل [js/app.js](../js/app.js). البنية الحالية تحتوي على:

1. `product-index-outer`: رقم المنتج في دائرة جانبية.
2. `card-header`: رأس البطاقة.
3. `product-title`: اسم المنتج والتصنيف والموقع.
4. `product-meta-wrapper`: الكمية وإجمالي التكلفة ونسبة الربح وزر العين.
5. `price-row`: أسعار الشراء والميكانيكي والبيع.
6. `action-buttons`: أزرار البيع والتعديل والحذف.

يجب عدم إزالة هذه العناصر أو تغيير معرفاتها لأن JavaScript يعتمد على معرفات الأزرار وبيانات `data-id` لتشغيل العمليات.

## أخطاء شائعة وأسبابها وحلولها

### 1. المنتجات تظهر في نصف الحاوية

السبب الأكثر احتمالًا هو أن `section-panel.active` يستخدم Flex باتجاه `row`، ولم يتم إعطاء `inventory-section-panel` اتجاهًا عموديًا.

الحل:

```css
.inventory-section-panel {
    flex-direction: column;
    width: 100%;
}
```

ثم تأكد أن `items-scroll-wrapper` و`items-container` بعرض كامل.

### 2. المنتجات تظهر بجانب بعضها

الأسباب:

- استخدام `display: grid` على `items-container`.
- استخدام `flex-direction: row` على قائمة المنتجات.
- وجود `grid-template-columns` موروث أو متأخر.
- عدم تطبيق الصنف `inventory-products-stack` على `itemsList`.

الحل:

```css
.inventory-products-stack {
    display: flex;
    flex-direction: column;
}
```

### 3. بطاقة المنتج لا تغطي كامل السطر

الأسباب:

- عدم وجود `width: 100%`.
- وجود `max-width` على البطاقة.
- وجود `align-items: flex-start` على الحاوية.
- وجود `flex: 0 1 auto` يسمح بانكماش البطاقة.
- وجود حاوية أم بعرض جزئي.

الحل:

```css
.inventory-products-stack {
    align-items: stretch;
    width: 100%;
}

.inventory-products-stack .product-card {
    flex: 0 0 auto;
    width: 100%;
    box-sizing: border-box;
}
```

### 4. أزرار الفلترة تظهر عموديًا

افحص `flex-direction` و`flex-wrap` في `filter-bar` و`inventory-filter-bar`. يجب أن تكون القيم:

```css
flex-direction: row;
flex-wrap: nowrap;
```

إذا كان العرض ضيقًا، استخدم التمرير الأفقي بدل `column`.

### 5. صف الترتيب ينزل إلى أكثر من سطر

هذا قد يكون مقصودًا فقط إذا كان العرض ضيقًا جدًا، لكن الاتجاه يجب أن يبقى أفقيًا. استخدم `overflow-x: auto` و`flex-wrap: nowrap` إذا كان المطلوب سطرًا واحدًا دائمًا.

### 6. وجود فراغ مضاعف بين بطاقات المنتجات

السبب هو الجمع بين:

```css
gap: 14px;
margin-bottom: 12px;
```

الحل هو ترك المسافة للحاوية فقط:

```css
.product-card {
    margin-bottom: 0;
}

.inventory-products-stack {
    gap: 14px;
}
```

### 7. اختفاء جزء من البطاقة

الأسباب المحتملة:

- `overflow: hidden` على البطاقة مع نص لا يلتف.
- `white-space: nowrap` على عنصر طويل.
- أبعاد ثابتة صغيرة للبطاقة.
- `height` ثابت أقل من المحتوى.
- حجم أزرار أو أسعار أكبر من عرض البطاقة.

الحل:

- السماح باسم المنتج بالالتفاف عبر `word-break: break-word`.
- استخدام `min-width: 0` لعناصر Flex الداخلية.
- تجنب الارتفاع الثابت للبطاقة.
- جعل النصوص الطويلة تلتف داخل المساحة.
- مراجعة الحشو وحجم الخط في نقاط الشاشة الصغيرة.

### 8. خروج المحتوى خارج البطاقة

افحص العناصر التالية داخل البطاقة:

- `product-title` يجب أن يملك `min-width: 0`.
- `product-name` يجب أن يستخدم `word-break: break-word`.
- العناصر ذات `white-space: nowrap` يجب ألا تحتوي نصًا طويلًا بلا مساحة.
- `price-col` يجب أن يسمح للقيم الطويلة بالانكماش أو الالتفاف.
- الأزرار يجب أن تستخدم مساحة البطاقة المتاحة دون عرض ثابت كبير.

### 9. ظهور البحث مرتين

النسخة القديمة كانت تضع البحث داخل قسم المخزون، أما النظام الأساسي فيضعه في `sticky-search-bar` المشترك بين الأقسام. عند تطبيق بنية `oldxmetal`:

- لا تنسخ حقل البحث من `oldxmetal/index.html` إلى قسم المخزون.
- حافظ على الحقل الحالي `searchItemsInput` في الشريط العام.
- لا تنشئ عنصرًا ثانيًا بالمعرف نفسه، لأن ذلك يسبب سلوكًا غير متوقع في JavaScript.

## أولوية CSS عند التشخيص

3. `display` و`flex-direction` و`width` في `itemsList`.

## قواعد ثابتة للمستقبل

- لا تنقل شريط البحث العام من مكانه.
- لا تضف حقل بحث جديدًا بمعرف `searchItemsInput`.
- لا تجعل `section-inventory` يعمل باتجاه Flex أفقي.
- لا تحول قائمة المنتجات إلى Grid إذا كان المطلوب بطاقة واحدة كاملة العرض في كل سطر.
- لا تضع `flex-direction: column` على `inventory-filter-bar`.
- لا تستخدم ارتفاعًا ثابتًا صغيرًا لبطاقات المنتجات.
- لا تجمع بين `gap` وهامش سفلي إضافي للبطاقة بلا سبب.
- لا تغير معرفات عناصر HTML التي يعتمد عليها `app.js`.
- لا تضف قواعد عامة على `.items-container` إذا كان المطلوب خاصًا بالمخزون؛ استخدم `.inventory-products-stack`.
- لا تستخدم `!important` قبل فهم سبب التعارض في ترتيب CSS.
- افحص قواعد `@media` بعد كل تعديل responsive.
- قارِن دائمًا مع `oldxmetal/index.html` و`oldxmetal/css/styles.css` عند إصلاح ترتيب المخزون.

## النتيجة المرجعية

التنسيق الصحيح لقسم المخزون هو:

- البحث العام ثابت في الشريط العلوي.
- صف علوي أفقي للترتيب وأسعار الميكانيكي.
- صف ثانٍ أفقي للفلاتر: الكل، المتوفرة، المنتهية.
- قائمة منتجات أسفل الفلاتر.
- بطاقة منتج أفقية كاملة العرض في كل سطر.
- المنتجات فوق بعضها مع مسافة `14px`.
- اتجاه البطاقة `rtl`.
- القسم الأم باتجاه `column`.
- لا توجد منتجات في نصف الحاوية.
- لا توجد فلاتر عمودية.
- لا توجد نسخة ثانية من شريط البحث.

## دورة البيانات الكاملة

### المصدر الأساسي

- المصدر الدائم للمنتجات هو مجموعة Firestore باسم `items`.
- يتم تحميل المنتجات من `db.collection('items')` داخل `js/app.js`.
- عند توفر اتصال مستمر، يستقبل النظام التغييرات عبر `onSnapshot` ويعيد تحديث `allItems` ثم يعيد رسم القائمة.
- عند التحميل الأول يمكن استخدام التخزين المؤقت المحلي بالمفتاح `xmetal_cache_items` لتسريع العرض.
- الحالة المشتركة تحفظ المنتجات في `appState.data.items`، بينما يبقى `allItems` مرجع التوافق الذي تستخدمه الدوال القديمة.
- دالة `updateAllItems(items)` تزامن القائمة مع `appState` وتستدعي `renderInventory()` عند وجود `itemsList`.

### الحقول المستخدمة في البطاقة

تعتمد البطاقة على كائن المنتج القادم من مجموعة `items`، وأهم الحقول هي:

- `id`: معرف المنتج، ويستخدم في `data-id` وربط أزرار البيع والتعديل والحذف والعين.
- `name`: اسم المنتج.
- `categoryName`: اسم الفئة إن وجد.
- `location`: موقع المنتج إن وجد.
- `quantity`: الكمية الحالية، وتستخدم أيضًا لتحديد الفلتر وحالة المخزون.
- `purchasePrice`: سعر الشراء.
- `salePrice`: سعر البيع.
- `mechanicPrice`: سعر الميكانيكي، مع استخدام سعر البيع كبديل إذا لم توجد قيمة.
- `purchaseBatches`: دفعات الشراء إن كانت مفعلة؛ تستخدم لحساب متوسط التكلفة ورأس المال.

### الحسابات قبل العرض

- `getItemInventoryCapital(item)` يحسب رأس المال: مجموع `quantity × unitCost` من `purchaseBatches`، أو `purchasePrice × quantity` عند عدم وجود دفعات.
- السعر الثانوي يحسب عبر `convertToSecondary()` وفق إعدادات العملة الحالية.
- نسبة الربح تحسب من سعر البيع وسعر الشراء وفق المعادلة `(salePrice - purchasePrice) / purchasePrice × 100`.
- حالة المخزون تكون `out-of-stock` عند كمية تساوي صفرًا، و`low-stock` عند كمية أقل من أو تساوي `2`، وإلا تكون البطاقة عادية.
- القيم المعروضة تمر عبر `formatMoney()` أو `fmtMoney()` قبل إدخالها إلى HTML.
- اسم المنتج والفئة والموقع تمر عبر `escHtml()` لمنع إدخال HTML غير مقصود من بيانات المستخدم.

## عمل البحث والترتيب والفلاتر

### البحث العام

- الحقل `searchItemsInput` موجود في `sticky-search-bar` المشترك بين الأقسام.
- عند الكتابة فيه، يجعل النظام القسم الحالي `inventory` ويستدعي `renderCurrentSection()`.
- البحث يمرر النص إلى `filterAndSortProducts(term, currentInventoryFilter)`.
- تتم مطابقة النص مع `p.name`، مع إعطاء أولوية للاسم الذي يبدأ بالنص ثم للكلمات التي تبدأ به.
- لا تضف حقل بحث ثانيًا داخل قسم المخزون، ولا تغير معرف الحقل العام.

### زر الترتيب

- الزر هو القائمة `inventorySortSelect`.
- الخيارات هي `alphabetical` و`purchase` و`sale` و`quantity`.
- عند تغييره تستدعي الصفحة `persistInventorySort()` ثم `renderInventory()`.
- يحفظ الاختيار في `appState.filters.inventorySort` وفي `localStorage` بالمفتاح `xmetalInventorySort`.
- `sortInventoryList()` يستخدم `PriceHelpers.sortInventoryProducts()` إذا كانت متاحة، وإلا يستخدم المقارنة المحلية.
- عند تساوي القيم الرقمية، يستخدم النظام الترتيب الأبجدي العربي كترتيب ثانوي.

### أزرار الفلترة

- الأزرار داخل `#inventoryFilterBar .filter-btn`.
- `all`: يعرض كل المنتجات.
- `available`: يعرض المنتجات التي `quantity > 0`.
- `outofstock`: يعرض المنتجات التي `quantity === 0`.
- عند اختيار زر، تزال `active` من بقية الأزرار، وتضاف للزر المختار، ثم يعاد استدعاء `renderInventory()`.
- الفلترة والترتيب يعملان معًا؛ الفلترة تحدد المجموعة أولًا، ثم يطبق الترتيب عليها.

## إظهار وإخفاء الأسعار

### زر العين داخل كل بطاقة

- زر العين يحمل `data-id` الخاص بالمنتج.
- الحالة المحلية `itemVisibility[item.id]` تحدد هل تفاصيل ذلك المنتج ظاهرة.
- عند الضغط، تعكس الدالة القيمة ثم تستدعي `renderInventory()`.
- عندما تكون الحالة مخفية، يضاف `blur-price` إلى:
    - إجمالي تكلفة المنتج.
    - نسبة الربح.
    - سعر الشراء الأساسي.
    - السعر الثانوي لسعر الشراء.
- سعر البيع يبقى ظاهرًا، لأن زر العين الفردي مخصص لتفاصيل التكلفة والربح.
- الإخفاء البصري لا يحذف البيانات ولا يغيرها من Firestore؛ هو حالة عرض محلية فقط.
- `blur-price` يستخدم `filter: blur(5px)` مع `user-select: none`.
- زر العين نفسه يغير أيقونته بين `fa-eye` و`fa-eye-slash` حسب الحالة.

### زر أسعار الميكانيكي العام

- الزر هو `toggleAllMechanicPricesBtn`.
- الحالة `showMechanicPricesGlobally` تتحكم في أسعار الميكانيكي لجميع البطاقات.
- عند الضغط، تتغير الحالة، ثم تستدعى `updateInventoryGlobalEyeButton()` و`renderInventory()`.
- عند الإخفاء يضاف `blur-price` إلى سعر الميكانيكي الأساسي والثانوي فقط.
- لا يغير هذا الزر سعر الشراء أو سعر البيع أو إجمالي التكلفة.
- `updateInventoryGlobalEyeButton()` يغير الصنف `active` وأيقونة الزر لتوضيح الحالة.
- هذه الحالة أيضًا محلية للعرض ولا تعدل سجلات المنتجات.

### الفرق بين حالتي الإخفاء

| الحالة | نطاق التأثير | مصدر الحالة | هل تعدل قاعدة البيانات؟ |
| --- | --- | --- | --- |
| زر العين داخل البطاقة | تكلفة المنتج والربح وسعر الشراء | `itemVisibility[item.id]` | لا |
| زر أسعار الميكانيكي | سعر الميكانيكي الأساسي والثانوي في كل البطاقات | `showMechanicPricesGlobally` | لا |

## أزرار بطاقة المنتج

### زر البيع

- يحمل الصنف `sell` و`data-id` للمنتج.
- عند الضغط يستدعي `openSellModal(itemId)`.
- إذا كانت الكمية صفرًا، يضاف `disabled` ولا يسمح بالبيع.
- لا تضع منطق البيع داخل CSS أو داخل البطاقة؛ المنطق موجود في `openSellModal()` ومعالجة نموذج البيع في `js/app.js`.

### زر التعديل

- يحمل الصنف `edit` و`data-id`.
- يستدعي `editItem(itemId)` لقراءة المنتج وتعبئة نموذج التعديل.
- بعد الحفظ يحدث سجل `items` ثم تستدعى `renderInventory()` عبر تحديث البيانات.

### زر الحذف

- يحمل الصنف `delete` و`data-id`.
- يطلب تأكيد المستخدم أولًا.
- عند التأكيد يحذف المنتج من `db.collection('items').doc(itemId)`، ويسجل العملية، ثم يزيله من `allItems` ويعيد الرسم.
- لا تغير أسماء الأصناف أو `data-id` لأن ربط الأحداث يعتمد عليها.

## دورة إعادة الرسم

الدالة المركزية هي `renderInventory()`، وتعمل بهذا التسلسل:

1. تقرأ قيمة `searchItemsInput`.
2. تستدعي `filterAndSortProducts()` باستخدام النص والفلتر الحالي.
3. تنشئ HTML لكل منتج بالترتيب الناتج.
4. تحسب النسبة والتكلفة والأسعار الثانوية وحالة المخزون.
5. تطبق حالات الإخفاء الفردية والعامة.
6. تضع الناتج في `document.getElementById('itemsList').innerHTML`.
7. تربط أزرار البيع والتعديل والحذف والعين بالمنتجات.

لذلك لا تعدل DOM يدويًا لبطاقة واحدة بعد الرسم إلا إذا كان هناك سبب واضح؛ أعد تحديث الحالة ثم استدع `renderInventory()` حتى تبقى جميع البطاقات متزامنة.

## حالات البيانات الخاصة

- لا توجد منتجات: يعرض `empty-state` برسالة `لا توجد منتجات`.
- لا توجد فئة: لا ينشأ `product-category-tag`.
- لا يوجد موقع: لا ينشأ `product-location-tag`.
- لا يوجد سعر ميكانيكي: يستخدم النظام سعر البيع كبديل للعرض.
- كمية صفر: يمنع زر البيع وتظهر حالة نفاد المخزون.
- كمية أقل أو تساوي `2`: تظهر علامة المخزون المنخفض.
- اسم طويل: يجب أن يلتف داخل `.product-name` ولا يوسع الحاوية.
- سعر أو نسبة طويلة: يجب أن تنكمش أو تلتف داخل الأعمدة دون خروج أفقي.
- خطأ في التحميل: يجب الإبقاء على البيانات المخبأة إن وجدت، وإظهار الخطأ عبر مسار معالجة الأخطاء بدل كسر الصفحة.

## مطابقة oldxmetal

النسخة المرجعية القديمة توفر المبدأ التالي:

- `items-container` يستخدم `display: flex`.
- الاتجاه `column`.
- بطاقة منتج فوق البطاقة التالية.
- `gap: 14px`.
- بطاقة المنتج بعرض الحاوية.
- شريط الأدوات في أعلى القسم.
- الفلاتر في صف أفقي واحد تحت شريط الأدوات.

عند نقل المبدأ إلى النظام الأساسي:

- انقل ترتيب العناصر، وليس شريط البحث الداخلي القديم.
- احتفظ بشريط البحث العام الحالي.
- استخدم الأصناف الخاصة `inventory-section-panel` و`inventory-products-stack` لتجنب التأثير على حاويات أخرى.
- لا تستبدل قائمة المنتجات بشبكة أو `auto-fit` إذا كان المطلوب بطاقة واحدة كاملة العرض في كل سطر.
